## 任务剖面

按模块逐一分析，最终给出综合结论。请覆盖以下八块：

### 1. 架构与分层
- 对照 `03-系统总体架构设计.md`，检查「采集层 / AI决策层 / 执行层 / 调度监控层」在真实代码中的落地情况：哪些有实现、哪些只是设计、哪些缺口。
- 数据流闭环（投放 ROI 回写→选品/素材）在代码里是否有真实打通，还是仅契约。

### 2. 模块逐块评估（M0~M6）
对应 `_management/modules/m0-foundation ~ m6-frontend`，每个模块回答：
- 交付物是否完整（brief/progress/decisions/BLOCKERS/database 迁移）
- 真实实现落在 `backend/` 的哪些文件/服务/表
- 声称进度（如 M1 97%、M4 100%）与代码成熟度是否匹配
- 阻塞与风险
- 用一张表汇总：模块 | 声称进度 | 代码实现位置 | 成熟度判断 | 主要风险

### 3. 后端设计质量
- 数据库模型、模块隔离（宪法要求一模块一库 + 表前缀）是否落实
- 幂等/断点/错误码分类（VERIFICATION_REQUIRED/AUTH_REQUIRED/RATE_LIMIT/TIMEOUT/NO_MATCH/PLATFORM_REJECT/UNEXPECTED）是否一致实践
- 配置化（路径/白名单/权重/阈值走配置）落实情况
- 测试质量与覆盖薄弱点
- 49 个临时 `_*.py` 脚本提示了什么卫生问题

### 4. 前端控制台
- Next.js 路由/页面 / FastAPI API 路径与后端是否对得上
- 鉴权、CORS、密钥处理是否达标
- 与后端数据契约（join、媒体端点待办）缺口

### 5. 外部集成与自动化风险
- 上架双轨制（OpenAPI 主链路 + Playwright 兜底）：主链路实现到什么程度，是否仍是 mock
- Playwright/CDP 自动化（淘宝/1688/有米云/罗盘）的健壮性、风控暴露面、登录态依赖
- 素材生成（AI 主图/文案）：DB 是否真接大模型，还是 Pillow 占位/规则降级
- 关键外部依赖与账号/登录态前置项清单

### 6. 数据与合规
- 数据模型跨模块流动是否按 `data-audit.md` 会签
- 合规三态、硬拦词表、相关性门、人工闸门在 `10-风险合规与风控清单.md` 与代码里的对齐
- 金额「分」int、时间 UTC 等 REC 决策是否落实

### 7. 工程卫生与治理
- git 版本纪律（每步可回退、标签）、_management 治理过程质量、踩坑日志(P-n)闭环
- 未被 git 追踪的运行时资产（data/、browser profiles、.pytest-tmp）是否合理
- 依赖/构建是否有明显隐患（后端 requirements 缺项、前端 overrides、旧 .next 产物）

### 8. 综合结论
- 一句话总结这个仓库当前真实状态
- 成熟度高（可借鉴）与成熟度低（风险大）的各 3~5 点
- 按「最有价值」排序，给出 5~8 条可执行的下一步建议（含优先级、理由、涉及文件/模块）
