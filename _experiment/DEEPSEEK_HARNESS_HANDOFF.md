## 任务边界

本轮只做重构前的系统理解、问题复核和优先级梳理：不编写代码、不修改现有实现、不把 mock/fixtures 验收当作真实平台能力。

## 项目判断

视频号微信小店自动化系统包含 M0 基座、M1 选品、M2 素材、M3 优化、M4 上架、M5 投放和 M6 控制台。

当前仓库的业务规则、状态机、离线 fixtures 测试和 M1 部分真实采集较完整；M4/M5 真实写平台能力、M2/M3 多条真实链路、以及 ROI 自动回流仍未闭环。因此它应被视为可复用的原型和规则资产，而不是可直接扩展的生产底座。

完整静态证据报告：`_experiment/codex-project-analysis/REPORT.md`。

## 已确认的核心问题

1. **M4 真实上架未落地**：`backend/adapters/wechat_openapi.py` 默认 `mock`，`LIVE_API_PATHS` 未填；`backend/listing/ui_fallback.py` 只有 `MockPageOps`。
2. **M5 真实投放与报表回读未落地**：`backend/ads/executor.py` 的真实 CDP connector 未完成；`backend/ads/report.py` 只规范化外部传入 rows，未获取真实报表，也未提供真实定时器。
3. **ROI 回流只是交换契约**：M5 可写交换文件，M1/M3 可显式摄取；没有“真实报表回读 -> 自动回写 -> 下一批决策”的运行编排。
4. **M2/M3 真实产物与降级产物混杂**：淘宝/1688 素材采集默认 fixtures；M3 无 Key 时分别走 Pillow 占位图和规则文案；真实 img2img 只出现在临时脚本，未进入正式流水线。
5. **M1 的真实采集可用但脆弱**：CDP 采集与询价有运行证据，也记录了登录失效、URL 时效、平台限流、风控熔断和低频断点续跑。参见 `_management/logs/pitfall-log.md` 的 P-039、P-040、P-046。
6. **数据库演进不完整**：M0 外大部分模块依赖 SQLAlchemy `create_all`，缺少增量迁移；M2 历史运行库缺列已引发 API 500。
7. **M6 是开发态后台**：默认内存 fixtures 会话，重启失效；密码使用 SHA-256，cookie 未强制 Secure；生产 CORS、存储根和初始化流程未确认。
8. **合规门存在生产放行边界**：素材相关性为空时兼容放行；M3 高风险类目默认空、人工抽检默认 10%，需配置和审计证明。
9. **治理信息有漂移**：v0.81-v0.83 未建对应 Git tag；实验、运行资产与临时测试文件混杂；管理看板部分结论落后源码。

1. 全链路产物必须记录并展示 `mode/provider/model/source/evidence`，明确真实、模拟、规则降级和占位图。
2. 定义一件商品的最小真实验收链：选品 -> 素材 -> 上架 -> 托管 -> 两次报表回读 -> ROI 回写。
3. 冻结 M4 OpenAPI、M5 页面/接口、错误码、幂等键、人工接管和回滚契约。
4. 建立 M0-M5 的数据库迁移、版本检查和回滚策略，禁止再以 `create_all` 作为生产演进机制。
5. 为企业资质、类目、运费模板、账户余额、独立登录态、ffmpeg、对象存储、模型凭据建立启动前置检查。
6. 在真实写入链路验收前，M4/M5 只能标记为骨架/模拟，不能计为已完成。
