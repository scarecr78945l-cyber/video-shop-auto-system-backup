## 2026-08-02-kaogujia-continuous-pagination-plan.md（2026-08-02）｜ 选品采集·连续翻页调度
- 摘要：考公家（Kaogujia）榜单逐页持续扫描直到真实最后一页，逐页 checkpoint，按中国本地日次日从第一页重置重启。
- 决策要点：
  - 背景动机：按页扫描此前会提前停止或每日只扫前几页，榜单后部商品长期漏采；目标是每个启用榜单全页覆盖。
  - 关键取舍：翻页游标按"整页大小"推进而非"过滤后存活候选数"推进——过滤会减少候选数，按存活数推进会导致页码错乱、漏页；批次改为 list 兼容的 SourceCandidateBatch（元数据挂在 batch 上），避免破坏既有 Youmi/Kaogujia 调用方。
  - 硬约束：只复用现有 Kaogujia 标签页，不按排名页新开页面；不设业务页数上限；仅在确认末页/登录验证/风控等待/用户暂停/取消/服务关闭时停止；品牌、服饰、食品、高退货风险、365 天重复过滤永不阻止翻页。
  - 防循环设计：连续两次 page fingerprint 相同视为重复页，当日停止，杜绝死循环；checkpoint（completed_for_date、last_page_fingerprint、scanned_pages 等）落库，后台重启后从断点续扫。
  - 次日重置：中国本地日历日切换后已完成榜单从 offset 0 重启，保证每天全量重扫一遍。
- 里程碑/验收要点：
  - 页元数据契约：SourceCandidateBatch 带 page_number/page_size/row_count/has_next_page/end_reached/page_fingerprint，适配器不点击即可读翻页状态。
  - 持久化每日进度字段 + prepare_board_for_local_date 重置昨日完成态。
  - 调度器：has_next_page=True 立即调度下一页（即使本页零合格候选）；end_reached=True 记当日完成并安排到次日；重复指纹当日停止。
  - 真实共享浏览器验收：同一标签页翻页≥3 页、checkpoint 在重启后存活、全程零真实订单/客服消息/草稿/发布。

## 2026-08-03-kaogujia-board-coverage-and-filter-recovery-plan.md（2026-08-03）｜ 选品采集·榜单覆盖与筛选恢复
- 摘要：为榜单路由、轮询配置、误判标题和风险分层补失败测试；新增热门视频榜/图文带货榜路由与轮询；收窄姓名/IP 推断，放行营销方括号，把「安装」降为人工确认；重启后端后非破坏性重扫。
- 决策要点：
  - 收窄误判源：姓名/IP 推断只对明确证据或姓名形态硬拦截——修复过宽规则误杀普通日用品（与 specs 08-03 同口径）。
  - 营销词降级：白名单营销方括号（买一送一/拍一发二/包邮/加厚升级等）放行；「安装」从硬拦截降为人工确认——营销措辞不是风险证据。
  - 覆盖扩展：热门视频榜、图文带货榜加入路由与轮询计划。
- 里程碑/验收要点：
  - 定向测试 + 完整选品测试通过后重启后端，执行非破坏性重扫。
  - 按榜单报告扫描、风险过滤、重复过滤、实际入库数量——修复效果以重扫实测为准，不凭历史日志估算。

## 2026-08-04-kaogujia-five-board-selection.md（2026-08-04）｜ 考古加五榜选品
- 摘要：把考古加自动选品限制为五个「商品」菜单榜单（实时销量/视频热推荐/商品热销/商品数据大盘/往年爆款），榜单目录单点权威，逐页顺序采集 + checkpoint 直到真实末页。
- 决策要点：
  - 固定五榜白名单：`KAOGUJIA_SELECTION_BOARDS` 不可变目录为唯一权威，调度器与适配器共同校验，禁止从页面自动扩展榜单——防页面/菜单变化导致范围漂移。
  - 同名异义显式区分：视频热推荐榜必须是商品菜单的「商品视频热卖排行」，不是通用视频内容榜。
  - 旧榜停用不销毁：`disable_boards_except` 持久化停用五个旧内容榜（status=disabled/next_run_at=None），保留历史数据与审计线索；新五榜从第一页建立独立断点。
  - 顺序翻页纪律：当前页完成抽取→过滤→写库→页证据→checkpoint 保存后才推进游标；`requested_page==page_number` 才接受成功 checkpoint，异常时游标不变——「页面已提交」是翻页前置条件，不允许跨页导航。
  - 页指纹防循环 + 次日重置：末页判定后 `completed_for_date=中国本地日`、`next_run_at=次日`，当天不再回第一页。
  - 无 Git 约束：任务检查点 = 测试结果 + 数据库备份（而非提交）。
- 里程碑/验收要点：
  - 调度状态只有指定五榜可运行，旧榜不再产生新扫描记录；真实共享浏览器连续两页验证（同标签页复用、页码/指纹/行数/入库统计齐全）；末页正确停止不循环回第一页。

## 2026-08-10-sourcing-pipeline-optimization-plan.md（2026-08-10）｜ 选品链路优化
- 摘要：把考古加与有米云接入统一选品账本，降低误判与同款素材门槛，询价/生图/图片审核/上架阶段具备可恢复、可观测状态；来源适配器只采集、调度器管断点/频率/去重、流水线管风险分层。
- 决策要点：
  - 职责分层：适配器只负责采集，调度器负责断点/频率/去重，流水线负责风险分层与后续队列——单一职责边界（与新系统 M0 调度器设计同思路）。
  - 来源账本幂等：候选入库用稳定 `platform+board+source_item_id`，跨页同源合并证据不重复创建 Product——防重复入库存单一事实源。
  - 有米云归一化：适配器返回与考古加一致的 `SourceCandidate` 字段（source_item_id/name/category/board/source_url/image_url/价格等）；未登录返回 `waiting_login` 不创建候选。
  - 风险三态 + 门槛放宽：`hard_reject/candidate/manual_review` + 结构化 risk_reasons；同款素材最低条件 = 一张高置信主图 + 一张细节图（标准仍 3+3）——降低「数据完备」门槛到「证据可用」，品牌硬拦不回归。
  - 失败隔离到商品：单商品验证码 `waiting_verification` 保存 product_id/job_id/page_url/attempts/resume_after，用户完成后恢复当前页，其他商品继续排队——人工接管不断链。
  - 状态显式化：按钮操作返回 request_id/product_id/status/next_action/error_code；漏斗统计十项（扫描/去重/风险/入库/同款/询价/生图/审核/可上架/已上架）。
- 里程碑/验收要点：
  - 账本幂等（同源两次只建一次）、有米云归一化 + 登录暂停、风险三态 + 放宽参考门禁且品牌硬拦不回归、验证码单商品暂停其他继续、进程重启恢复、漏斗统计与落库对账。

## 2026-08-11-listing-title-and-main-image-rules.md（2026-08-11）｜ 标题与主图硬规则
- 摘要：淘宝标题 15–35 有效字符（仅 Unicode 字母数字计数、机械截断）与至少 5 张正方形主图的硬门槛，规则集中在单一内容规则模块，四处入口同源。
- 决策要点：
  - 规则集中化：标题/图片常量集中在 `listing_content_rules` 单一模块，淘宝摄取/图片审核/上架门禁/上传归一化共用——每个入口结果一致，防口径漂移。
  - 标题只机械截断：保留淘宝源标题、超过 35 有效字符仅机械截断不 AI 改写（防改写改变事实）；不足 15 由门禁阻止。
  - 五主图硬门槛：四张主图阻塞；审核阶段禁止排除最后五张中的主图；详情图可转换为缺失的正方形主图槽位；无可用详情图 → 保持「待补图」不淘汰不进入上架。
  - 迁移包联动：更新 CHAT_HANDOFF.md、重新生成迁移 manifest 与 ZIP 并校验哈希——迁移包可追溯（与本轮 P2-4 MANIFEST 机制同源）。
- 里程碑/验收要点：
  - 14 字符拦截、15–35 通过、>35 机械截断；空格/标点/表情不计长；四张主图拦截、五张可继续、任一主图非正方形拦截；全量回归 + 前端构建 + 迁移包哈希校验。

## 2026-08-11-wechat-douyin-compass-sourcing.md（2026-08-11）｜ 微信商机+抖店罗盘接入
- 摘要：方案 A（独立适配器 + 通用调度策略）：微信商机中心与抖店电商罗盘接入自动选品轮转；罗盘只扫 4 类榜单 × 3 类目 × 时间窗口 = 30 组合；实时爆品榜排除直播语义；每页先滚动到底再逐页扫描到终止证据。
- 决策要点：
  - 方案选型 A：独立适配器 + 通用调度策略，不改造既有采集器——新平台接入不改动已稳定渠道。
  - 罗盘 30 组合目录：商品卡/短视频/同行低退 3 榜 × 3 类目 × 3 时间窗口 + 实时爆品挖掘榜（仅 3 类目、不伪造时间窗口）；组合键稳定（榜单/类目/窗口）——目录驱动防硬编码漂移。
  - 直播语义过滤：纯函数 `contains_live_semantics` 排除 直播/直播中/正在直播/直播间/直播带货/直播开始时间 等；短视频带货/发布时间/商品卡 不被误杀。
  - 通用分页策略化：考古加的翻页/指纹/锚点/实时频率抽成平台策略；kaogujia/douyin_compass 注册分页策略、wechat 注册滚动锚点策略——一套已验证模式多处复用。
  - 自适应频率：微信商机中心 120 分钟；实时爆品组合 60 分钟、其他罗盘组合 1440 分钟；连续 24 次无新品降为 1440、发现新品恢复 60——用「新品证据」驱动频率。
  - 候选 ID 兜底：无商品 ID 时用来源链接/标题/店铺/图片指纹生成稳定 ID；source_url 必须指向商品或可复现榜单记录，禁止整页榜单 URL 导致同源误去重。
  - 阻塞隔离：等待登录/验证/页面变化只暂停当前平台/组合，不阻塞整轮选品。
- 里程碑/验收要点：
  - 30 组合自动轮转且不重复全量扫历史；实时榜直播全排除、短视频保留；单页完整滚动后才抽取、逐页扫描到明确终止证据；失败平台不阻塞其他渠道；新增测试 + 全量回归 + 前端构建 + 真实浏览器只读复验（零真实订单/草稿/发布）。

## 2026-08-14-automatic-promotion.md（2026-08-14）｜ 自动投放
- 摘要：已确认微信小店发布 → 有米云素材采集 → 本地去重下载 → 内容校验 → 微信广告创建 → 每日 ROI 维护的自动投放闭环；独立浏览器阶段保证失败可重试、登录闸门不阻塞无关工作。
- 决策要点：
  - ROI 领域模型：`promotion_metrics(售价-成本-运费, 退费率=10%, 费率=7%)` → break_even_roi；目标 ROI = 保本 + 0.2；连续 2 天零花费目标 ROI 降 0.02、不低于保本线（新系统 M5 同源：P1-5 ROI 计算器）。
  - 有米云素材收集：固定端口 9333 O50 浏览器；路径 = 有米云 > 素材 > 商品广告素材按关键词搜索；下载每个唯一匹配素材直到滚动/分页无新素材；URL/文件指纹去重；落盘 `runtime/promotion_materials/<product_id>/`——断点式收集。
  - 内容校验三态：确定性检查（标题/关键词相关性、禁类目拒绝、重复拒绝、不确定人工告警）为主，配置 AI 复核为二级闸门；保留 pass/fail 原因、不删源证据。
  - 广告创建幂等：初始预算 5000；campaign ID/URL + 提交证据落库后才标记 active；登录阻塞只停该阶段并发用户告警，其他计划继续。
  - 每日监控幂等：每日一次巡检、持久化 next-run 状态；平台要求加预算时记录 before/after 证据；登录/验证/页面变化/驳回只告警不阻断其他计划。
- 里程碑/验收要点：
  - ROI 计算与 0.02 地板规则测试；素材收集持久化 + 去重；内容校验三态；广告创建幂等 + 证据落库；每日报告记录在盘；真实已发布商品跑通 campaign 证据 + 每日监控记录（未完成前计划保持未完成态）。
