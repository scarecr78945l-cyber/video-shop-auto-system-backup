# M2 自动收集素材 · 风险预判清单（risks）

> 开工前由总工程师撰写（已通读 pitfall-log P-001~P-007，此处只列 M2 模块内风险与新增预判，全局风险引用不重复）。
> 每条格式：风险 | 影响 | 概率 | 应对方案。风险编号 R-M2-XX 供 BLOCKERS/台账引用。

## 〇、与全局踩坑日志的关系

- P-001（pytest 临时目录）：本模块所有测试命令统一 `--basetemp=".pytest-tmp"`，写入子代理任务书。
- P-002（平台登录态失效）：采集链路按 `AUTH_REQUIRED` 分类处理，不自动重试 → 人工登录 → 断点续跑。
- P-003（平台 UI 改版）：选择器/URL 全配置化 + `page_changed` 检测留证据 + 人工接管。
- P-004（硬编码路径与密钥）：路径/密钥全环境变量化；日志 `_redact_text` 脱敏；本模块绝不写明文 Cookie/Token。
- P-005（多模块共用单库）：本模块独立库 + `asset_*` 前缀 + 共享表只读 + data-audit 登记。
- P-007（素材不合规格）：硬规格校验写进标准化器与入库门禁（见下方 R-M2-06）。

## 二、外部 API 与接口（签名/反爬/TikTokDownloader）

| 编号 | 风险 | 影响 | 概率 | 应对方案 |
|---|---|---|---|---|
| R-M2-03 | **视频号下载签名与直链**：视频号无公开下载 API，直链需解析签名参数（如固定请求头/URL 参数），签名算法随版本变化 | 视频号采集器核心能力失效 | 高 | 自研采集器分两层：①页面/接口层拿视频 id 与作者信息（Playwright 共享浏览器，登录态在）；②直链解析层封装签名逻辑为**独立可替换模块**（`signer.py` 接口化），签名变化只改一个文件；全链路留证据 JSON（请求/响应摘要，不含 Cookie）；失败分类 `PLATFORM_REJECT`/`NO_MATCH` 退避 |
| R-M2-04 | **抖音/快手/小红书反爬**：接口签名（X-Bogus/msToken 等）、风控校验、频控 IP 限制 | TikTokDownloader 封装下载失败、账号被限 | 高 | 沿用 TikTokDownloader 社区维护的签名方案并**锁定版本**（requirements 固定版本号，升级需回归）；批量任务节流 0~4 级退避（间隔 ×1/2/4/8/16）；连续失败≥2 熔断暂停该平台（`risk_control` 探针恢复）；关键词/达人任务串行限量，避免触发频控 |
| R-M2-05 | **TikTokDownloader 对视频号支持弱**（主流版本主打抖音/快手/小红书，视频号源未适配或适配不稳） | 若依赖其下载视频号素材则必然失败 | 高 | **决策：视频号不依赖 TikTokDownloader**，单独自研视频号采集器（见 R-M2-03）；TikTokDownloader 仅用于抖音/快手/小红书，作为外部 CLI 进程调用（子进程+超时+输出解析），失败隔离不阻塞其他来源 |
| R-M2-06 | **平台接口限流/超时**（RATE_LIMIT/TIMEOUT） | 下载任务堆积、误判失败 | 高 | 沿用错误码体系：`RATE_LIMIT` 180s 退避、`TIMEOUT` 60s 退避、`NO_MATCH` 120s 退避；下载中台支持断点续传（HTTP Range）；任务租约 45min 过期回收，进程重启 `recover_after_process_restart` |
| R-M2-07 | 第三方下载 API（Douyin_TikTok_Download_API 类）稳定性/版权风险 | 直链服务宕机、合规问题 | 中 | 自建下载中台为主（多实例 HTTP API），第三方仅作参考实现，不直接依赖其公网服务；所有下载走本模块中台统一留痕 |

## 四、数据口径与污染

| 编号 | 风险 | 影响 | 概率 | 应对方案 |
|---|---|---|---|---|
| R-M2-11 | **双去重准确率不足**：视频 MD5 全量相同才判重（转码/加水印即变）；关键帧 phash 阈值不当（过严漏重、过松误删）；图片 phash 对不同压缩/裁剪鲁棒性差异 | 素材库重复堆积 / 误杀可用素材 | 高 | 三级去重：①文件 MD5（精确判重，入库前必查）；②视频关键帧 phash（取首/中/尾采样帧，汉明距离阈值配置化，默认经验值，先用 fixtures 校准再定阈值）；③图片 phash（复用 backend `sourcing/dedup.py` 的 image_phash 口径，保持跨模块一致）；指纹唯一约束防并发重复入库（对齐 `product_fingerprint_claims` 认领机制）；**去重阈值全部配置化**，先离线校准再上线 |
| R-M2-12 | 素材硬规格口径不一致（M2 入库 vs M3 输出 vs M5 绑定） | 下游绑定失败 | 高 | 硬规格常量集中定义（`materials/config.py`）：≥720×1280、9:16、MOV/MP4、≤500M、5~300s；入库与标准化双校验；与 M5 绑定前再校验一次（P-007） |
| R-M2-13 | 字段口径与 M3/M5 不一致（evaluation 取值、时长单位、文件路径语义） | 数据联动脏数据 | 中 | `context/README.md` 数据字典为唯一口径源；评估标签取值统一为枚举码（exploring/efficient/potential ↔ 探索期/高效/潜力）；跨模块交接走 `_management/data-exchange/` JSON + data-audit 登记（宪法第 5 节） |
| R-M2-14 | 来源 URL/达人信息缺失导致素材不可追溯 | 版权与投放追溯失败 | 中 | 入库强制要求 source_url + source_platform + source_author 非空（NOT NULL 约束）；证据 JSON 随素材留存 |

## 五、环境依赖

| 编号 | 风险 | 影响 | 概率 | 应对方案 |
|---|---|---|---|---|
| R-M2-15 | **ffmpeg 环境缺失/版本过旧**（11 文档前置条件"ffmpeg 待确认"） | 标准化器完全不可用 | 高 | 启动时探测 ffmpeg（`ffmpeg -version`），缺失则标准化任务立即报 `UNEXPECTED` 并留清晰错误；requirements 或 README 写明安装指引；ffmpeg 输出参数锁定（05 文档示例：`scale=720:1280:force_original_aspect_ratio=decrease,pad=720:1280:(ow-iw)/2:(oh-ih)/2 -t 300 -c:v libx264 -crf 23 -c:a aac`），参数集中配置便于微调 |
| R-M2-16 | 大文件转码资源占用（≤500M 素材转码耗时/内存） | 中台阻塞、超时 | 中 | 转码任务独立队列、并发上限配置化；转码超时与输出文件大小上限双重保护；临时文件与成品分离，失败清理临时文件 |
| R-M2-17 | 测试环境坑（P-001）与网络不可达（真实下载在开发/CI 不可用） | 测试无法跑、开发阻塞 | 中 | 测试统一 `--basetemp=".pytest-tmp"`；下载/采集逻辑全部配 fixtures 离线模式（对齐 sourcing），零登录态零网络可跑通全链路；真实下载只在集成环境验证 |

## 六、风控与合规

| 编号 | 风险 | 影响 | 概率 | 应对方案 |
|---|---|---|---|---|
| R-M2-18 | **素材版权风险**：搬运素材未标记来源/未做二创义务，平台投诉或法律风险 | 账号/店铺处罚、法律纠纷 | 高 | 只采集「可二创」来源；入库强制标记 source_platform/source_url/source_author 与二创义务（去水印/混剪/换文案）标签；敏感来源（影视剧/品牌官方）列入黑名单配置；素材仅作内部二创原料，二次分发前必须经 M3 二创 + M4/M5 审核链路 |
| R-M2-19 | **供应链词泄漏**：素材中出现 1688/工厂/源头/厂家/一件代发/批发 字样 | 平台拒审/虚假宣传处罚 | 高 | 复用 `compliance.py` 供应链词/品牌词过滤，预审在入库前执行；命中即标记 `compliance_status=rejected` 并记录命中词证据；标题/文案类字段单独强校验 |
| R-M2-20 | **平台拒审/源文件损坏素材继续投放** | 投放失败、资源浪费 | 中 | 对齐 05 设计：平台判「审核不通过或源文件损坏」的素材自动下架标记（upload_status/disabled 状态）；截图/证据留存；评估标签回流统计拒审原因（对齐 11 风险预案） |
| R-M2-21 | **批量采集触发平台风控（账号限流/封禁）** | 采集账号全灭 | 高 | 节流 0~4 级退避 + 连续失败熔断探针 + 批量任务串行限量 + 一键全停接入（10 文档四层防线）；下载与浏览动作错峰 |
| R-M2-22 | **文件存储：MinIO 暂缺**（11 文档 M4 才迁 MinIO/PostgreSQL/Redis） | 素材文件只能落本地磁盘，无对象存储 | 中（当前）/ 高（数据量增长后） | **当前方案**：`file_path` 指向本地素材目录（配置化 `MATERIALS_STORAGE_DIR`），DB 只存元数据；**过渡方案**：repo 层抽象存储接口（LocalStorage → MinIOStorage 可切换），文件路径语义统一为"存储键"；**远期**：M4 里程碑随全局迁移 MinIO，`file_path` 字段即 MinIO 键，迁移脚本放 `database/`；磁盘满监控告警 |
| R-M2-23 | 素材上传小店素材库（M3 后链路）失败/重复上传 | 投放绑定失效、素材库冗余 | 中 | upload_status 状态机（local→uploading→uploaded→failed/disabled）；幂等（platform_material_id 唯一约束）；上传失败退避重试，超限转人工 |
| R-M2-24 | 管理后台/接口无鉴权（10 文档"当前 API 全开放需补"） | 素材库/任务被外部调用 | 中 | 本模块接口沿用全局鉴权方案（总控统一补）；至少做到内部接口仅本机/内网可访问，密钥不落日志 |

## 七、风险登记纪律

- 新发现风险即时追加本文件并同步 `pitfall-log.md`（编号 P-008 起）与 `agent-activity.md`。
- 风险未解决但影响开发 → 按宪法第 6 节写 `BLOCKERS.md` 并结束回合等总控。
