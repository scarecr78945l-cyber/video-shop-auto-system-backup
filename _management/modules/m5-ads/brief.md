> 必读设计文档：08-自动小店投放模块设计（商品托管）.md、09、10、11、03

## 一、模块目标

对已上架「销售中」商品执行**全自动商品托管投放闭环**：选托管商品（选品 TopN）→ 自动进托管队列（≤50/批）→ 优选素材绑定（高效>潜力>探索期）→ 执行托管两步（添加商品/投放设置）→ 监控回读（曝光/花费/成交/补贴/诊断）→ 止损规则引擎 → 数据回写（选品「投放转化」维度 + 素材评估回流）。
为选品（M1）与素材（M2/M3）模块提供真实投放转化反馈，并在**预算三重硬约束 + 余额检测 + 一键全停**下控制资金风险。投放 = 商品托管模式（无转化不扣费、腾讯全域流量、平台自动投流），**不走腾讯广告 Marketing API**。

## 二、范围与边界

- **负责**：
  1. 托管候选池构建（读 M1 选品打分 TopN + 已上架状态；平台分桶标签作加分输入）
  2. 托管队列调度（≤50/批、多批串行、批间隔可配、防风控错峰）
  3. 素材优选与绑定（高效 > 潜力 > 探索期；无素材跳过标记「待素材」）
  4. 托管执行两步：① 添加托管商品 ② 投放设置（目标=成交ROI 默认/净成交ROI；目标ROI=系统推荐可覆盖；素材与视频号形象绑定）→ 提交
  5. 监控回读（投放列表：曝光/花费/成交金额/平台补贴/智能诊断）
  6. 止损规则引擎 + 余额检测 + 预算三重硬约束 + 一键全停
  7. 数据回写：选品「投放转化」维度；素材评估标签回流；托管失败原因回写商品 review_reason
  8. 托管看板数据（对齐后台列表列）供前端
- **不负责**：素材采集（M2）、素材二创与文案（M3）、商品上架（M4）、选品打分主体（M1，仅提供/消费「投放转化」维度数据）、腾讯广告 Marketing API 对接（本项目明确不走）
- **依赖其他模块**：
  - M1 选品：托管候选池输入（商品评分 TopN、状态=已上架/销售中）；「投放转化」维度回写目标方
  - M2/M3 素材：`assets` 表素材 + 评估标签（探索期/高效/潜力）→ 本模块 `ad_materials` 素材库映射
  - M4 上架：上架完成（官方 API 确认销售中）才可入托管队列
  - M0 基座：`workflow_jobs`/`workflow_runner`（复用租约/错误码/断点）、`app_config`（预算/阈值/权重配置化）、`logs`、`source_platform_states`（风控模式仿照 → `ad_account_states`）
- **对外提供**：
  - `ad_campaigns` / `ad_report_snapshots`（经总控协调后）→ M1 选品打分「投放转化」维度
  - 素材评估标签回流（投放实际效果更新 `evaluation`）→ M3 素材优化模板参数
  - 托管看板数据 → 前端托管页

## 三、交付物清单

| 交付物 | 验收标准 |
|---|---|
| `context/README.md` 数据字典 + 后台事实锚点 + 止损规则表 | 字段名/单位/枚举与 08 文档及后台截图一致；任何代理重启可独立续作 |
| `database/README.md` + `schema.sql`（ad_* 表） | DDL 可执行；主键/索引/唯一约束完整；金额单位口径明确（分） |
| `services/shop_ads/`（plan/session/executor/scheduler/report/stop_loss） | 幂等入队；错误码复用 09 码表；租约 45min；失败隔离 |
| `adapters/playwright_shop_ads.py`（托管执行器） | 添加商品+投放设置两步走通；选择器/URL 全配置化；page_changed 检测留证据 |
| 监控回读 + 止损规则引擎 | 定时回读快照入库；止损规则表逐条生效；余额<阈值暂停新增+告警 |
| 预算三重硬约束 + 一键全停 | 单笔/日总/计划总预算同时生效；任一超限即停；全停秒级生效 |
| 数据回写（选品维度 + 素材回流） | 回写字段口径与 M1/M3 协商一致并经总控 data-audit 核对 |
| 单元测试 + 模拟 E2E | `pytest --basetemp=".pytest-tmp"` 全绿；模拟批量/止损/预算场景 |
| `decisions.md` / `progress.md` / `BLOCKERS.md` 持续维护 | 关键决策有记录；进度实时更新；阻塞按宪法第 6 节上报 |

## 五、验收标准（总）

1. 全自动闭环链路数据可追踪：候选池 → 队列 → 执行 → 快照 → 止损 → 回写，每步留证据 JSON；
2. 资金安全：预算三重硬约束 + 余额检测 + 止损 + 一键全停四层防线全部可测试可触发；
3. 代码满足宪法第 8 节：可测试/幂等断点/错误分类/配置化/日志脱敏/文档同步；
4. 无明文密钥：投放账号凭证只写环境变量名。
