# M3 商品生图要求（供生图模型对接 · v1）

> 用途：微信小店商品上架主图 + 详情图（M4 消费）。本文档定义生图模型的**输入/输出/规格/合规**要求，模型侧需支持**图生图（img2img，参考原图保真商品本体）**，非纯文生图。

## 一、图类型与数量（每商品）

| 类型 | 数量 | 尺寸 | 用途 |
|---|---|---|---|
| 主图 main | **5 张** | **800×800（1:1）** | 商品详情首屏轮播（平台要求 5 张 1:1） |
| 详情图 detail | ≥1 张（标准 3 张） | 750×1000（3:4）或 800×800 | 详情页卖点/场景展示 |

> 5 张主图必须**视觉不同**（平台审核 + 系统 `images_duplicate` 去重校验：SHA256 不同 + 内容可辨）。不能是同一张图缩放。

## 二、5 张主图的标准变体（基于真实商品图生成）

| 变体 | 内容 | 说明 |
|---|---|---|
| main_0 | 商品主体居中 + **白/浅灰纯色背景** | 电商标准图，商品占画面 60-70%，顶部留安全区 |
| main_1 | **使用场景图** | 商品在真实场景（厨房/卧室/办公），背景虚化 |
| main_2 | **细节/特写图** | 放大商品核心卖点部位（材质/容量/功能） |
| main_3 | **卖点标注图** | 商品 + 2-4 个卖点角标（编号+短文案，对比度 ≥4.5:1） |
| main_4 | **对比图或补充场景** | 尺寸/新旧对比，或另一场景（如多色/容量展示） |

## 三、输入

| 项 | 内容 |
|---|---|
| 参考图 | 采集的真实商品图 1 张（URL 或 base64，商品本体来源） |
| 商品信息 | 标题（已清洗）、类目、真实卖点（来自 1688 标题/SKU，不虚构） |
| 变体指令 | 每个变体的目标描述（如"白色背景居中图"/"厨房使用场景"/"放大细节"） |
| 配色 | 主色从商品图提取，背景低饱和（≤商品图饱和度 60%） |
| 角标文案 | 由系统提供（合规预审后），模型只排布不生成文案 |

## 四、输出

| 项 | 要求 |
|---|---|
| 格式 | PNG/JPEG，**800×800 1:1 主图**；详情图 750×1000 或 800×800 |
| 质量 | 商品本体与参考图一致（货不对版=平台判罚+退货）；清晰无糊、无畸形 |
| 返回 | 图片二进制/URL（模型侧返回后，系统下载落盘 `backend/data/images/listing/<pid>/`） |
| 一致性 | 同一商品 5 张主图中商品本体、主色调一致（仅背景/构图/角标变化） |

## 五、合规红线（生图内容不得出现）

1. **不得改变商品本体**（形状/颜色/材质/品牌 LOGO 不得编造或篡改）——图生图必须锁定商品区域；
2. 不得出现**竞品品牌/商标/名人/IP**（如 Nike、明星同款字样）；
3. 不得生成**功效承诺**（"治病/根治/防脱"等）或虚假参数（M1 合规词库：BRAND_WORDS / PROHIBITED_WORDS / EFFICACY_WORDS / SUPPLY_CHAIN_WORDS）；
4. 不得出现平台禁用词（"官方旗舰店/唯一/第一"等绝对化用语）；
5. 角标文字由系统生成并预审，模型不得自由发挥文字内容（防幻觉/违规词）；
6. 图片不得含水印、联系方式、二维码（供应商带需裁掉——postprocess 已有 `crop_away_supplier_bands`）。

## 六、技术对接要求（模型侧）

1. **能力**：图生图（参考图 + 指令），**必须保真商品本体**；若支持 ControlNet/局部重绘更佳；
2. **API**：HTTP POST，输入 `{reference_image, prompt, size, seed}`，返回图片；或按你的模型规范，由我适配；
3. **并发/限流**：告知 QPS/日配额/超时，系统按令牌桶排队（RATE_LIMIT 180s 退避）；
4. **密钥**：环境变量 `WAN_API_KEY`（或你指定的变量名），不落库不落日志；
5. **超时**：单张默认 60s，支持重试（max_retries=2）。

## 七、现有代码对接点（M3 optimization）

- `optimization/images/provider.py`：`WanImageProvider`（现为 Wan **文生图** text2image——**不适用主图**，需改为图生图 img2img 或新增 img2img provider）；
- `optimization/images/planner.py`：生成每个变体的策略/prompt；
- `optimization/images/quality_gate.py`：生成后质量校验（分辨率/清晰度/本体一致性）；
- 落盘目录：`backend/data/images/listing/<pid>/main_{0..4}.png + detail_0.png`（M4 intake 直接消费）。
