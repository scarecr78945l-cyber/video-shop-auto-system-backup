# 组织架构与通讯协议（Org Chart）

> 更新：总控 Agent 负责维护。代理 ID 为运行时分配的会话标识。

## 一、架构总览

```
总控 Agent（本会话 = 总控会话）
├── M0 基座与数据治理 · 总工程师
├── M1 自动选品 · 总工程师
├── M2 自动收集素材 · 总工程师
├── M3 自动素材优化 · 总工程师
├── M4 自动上架 · 总工程师
└── M5 自动小店投放（商品托管）· 总工程师
      └── 各总工 → 子代理（开发任务级，可再递归）
```

## 二、角色职责

| 角色 | 职责 | 关键文件 |
|---|---|---|
| 总控 Agent | 全局决策、跨模块协调、备份与 GitHub 推送、向用户汇报、核对数据联动 | `master-session.md`、`dashboard.md`、`logs/data-audit.md` |
| 总工程师 | 模块全流程：读文档→任务书→风险→排期→建子代理→验收→迭代 | `modules/mX/brief.md`、`risks.md`、`progress.md`、`decisions.md` |
| 子代理 | 承接单个开发任务，产出代码/测试/文档，遇瓶颈上报总工 | `logs/agent-activity.md` |

## 三、通讯协议

1. **上行（子代理→总工→总控→用户）**：写文件 + 结束回合。
   - 子代理向总工汇报：写 `REPORT.md` 到本模块目录。
   - 总工向总控上报：更新 `progress.md` + `logs/agent-activity.md`，阻塞写 `BLOCKERS.md`，然后结束回合。
   - 总控向用户汇报：本会话回复 + `dashboard.md` 汇总。
2. **下行（用户→总控→总工→子代理）**：总控用 send_message 下发决策/任务，总工用 send_message 下发子代理。
3. **平级（模块间数据联动）**：禁止直接读对方数据库；走 `logs/data-audit.md` + 总控转达（见宪法第 5 节）。

## 四、备份协议

- 总控唯一执行 git：关键节点 `commit + tag + push`。
- 标签命名：`v<版本>`（例：`v0.1`、`m1-v1.0`）。
- 浏览器资料（登录态）与数据库文件不入库，符合风控纪律。
- GitHub 备份仓库：见 `github.md`。
