## 二、P0：直接可搬（新系统无对应物，优先级最高）

### P0-1 上架类目记忆 → M4

- **旧系统证据**：`services/listing_memory.py` + `category_listing_memory` 表
  - 字段：`manual_pass_streak` / `platform_image_rejection_streak` / `required_fields_json` / `sourcing_rules_json` / `image_rules_json` / `logistics_template` / `return_address_rule_json`
  - 语义：某类目历史人工通过后，**上架包自动预填必填参数、物流模板、退货地址**；平台拒审率升高则转人工复核
- **新系统现状**：`optimization/images/memory.py` 是**生图背景**类目记忆（background 轮换 white→scenario→gradient→lifestyle），**不是上架参数记忆**；listing 模块无类目记忆
- **融合动作**：
  1. M4 新增 `category_listing_memory`（或并入 listing 包表）：按类目累积通过/拒审/必填参数
  2. listing 包生成时优先取类目记忆预填（与 C2 客服补参联动：记忆中的 required_fields 决定哪些缺参需要问）
  3. 拒审率 ≥ 阈值 → 该类目转人工复核 + 记录平台驳回原因
- **验收标准**：fixtures 用例 ①某类目首单通过后，第二单上架包自动预填必填参数/物流模板 ②该类目后续拒审率超阈值 → 转人工

### P0-2 人审→规则草稿闭环 → M3 + M0

- **旧系统证据**：`services/human_learning.py` + `learning_feedback` / `learning_rule_drafts` 表
  - 语义：人工审核决定（approve/reject + 理由）→ 沉淀为规则草稿（stage/rule_key/rule_text/sample_count）→ 人工确认后生效
- **新系统现状**：有 A/B 评估（`ab/retrain.py`）与投放反馈（`ads/feedback.py`），**无"人审决定→规则草稿→确认→生效"闭环**
- **融合动作**：
  1. 在 `optimization/review/gate.py` 的人工判定出口接入反馈表（decision/reason/evidence）
  2. M0 定义规则草稿表 + 确认 API（对齐 DA-008 命名纪律）
  3. 草稿按 stage 聚类（素材规格/文案/主图/上架），满样本阈值后转人工确认生效
- **验收标准**：review gate 人工驳回 → 自动生成对应 stage 规则草稿；确认后新素材命中即按新规则判定

### P0-3 浏览器会话管理 → M0/M1

- **旧系统证据**：`wechat_session.py` / `alibaba_session.py` / `taobao_session.py`（has_profile/is_logged_in/last_url 探测）、`session_watcher.py`（轮询登录态 + resume_on_login）、`browser_paths.py`、`open_wechat_login.py` / `open_1688_login.py` / `open_taobao_login.py`、运维脚本 `restart9333.py`（重启保持登录态）
- **新系统现状**：collectors 直接连 CDP（9223/9555），**无统一会话健康检查**；登录态失效只能靠采集报错
- **融合动作**：
  1. M0 新增会话服务：按来源注册 CDP 端口/profile → 心跳探测登录态 → 失效上报 `AUTH_REQUIRED`（对齐 DA-008 码表）→ 阻塞对应来源采集
  2. M1 collectors 改走会话服务取连接，不自行假设登录态
  3. `browser_paths.py` 的浏览器发现逻辑（env 优先 + 候选路径表）原样搬，路径全部配置化
- **验收标准**：fixtures 模式模拟登录态失效 → 来源自动置 waiting_login，其它来源不阻塞；恢复后断点续跑

### P0-4 来源轮换 → M1 scheduler

- **旧系统证据**：`services/source_rotation.py`（9.2KB）——多源轮换采集（考古加/有米/罗盘），按间隔与失败状态切换，降低单平台风控概率
- **新系统现状**：scheduler 有账本/节流/熔断，**无轮换策略**
- **融合动作**：调度器选源时按 `next_run_at` + 失败计数轮换；单源连续失败 → 降权并切源
- **验收标准**：三源配置下调度 N 轮，无单源连续占用超过阈值；单源 risk_control 时其余源正常采集
