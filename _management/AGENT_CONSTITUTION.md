# 代理工作宪法（AGENT CONSTITUTION）

> 本文件是工作区内所有代理（总控/总工程师/子代理）必须遵守的顶层规范。
> 任何代理在开始工作前**必须首先阅读本文件**，再阅读自己的模块任务书与设计文档。
> 版本：v1.0（企业级标准）

## 0. 角色与汇报链

```
总控 Agent（本会话）
  ├── M0 基座与数据治理 · 总工程师
  ├── M1 自动选品 · 总工程师
  ├── M2 自动收集素材 · 总工程师
  ├── M3 自动素材优化 · 总工程师
  ├── M4 自动上架 · 总工程师
  └── M5 自动小店投放（商品托管）· 总工程师
        └── 各模块总工可创建子代理（子代理可再建下级子代理）

汇报链（自下而上）：
  子代理 → 本模块总工 → 总控 Agent → 用户
```

- **总控 Agent**：总控会话的唯一管理者。负责全局决策、跨模块协调、备份与 GitHub 推送、向用户汇报。
- **总工程师**：一个模块一个会话，负责该模块开发全流程管理（需求→设计→排期→分派→集成→验收→迭代）。
- **子代理**：由总工创建，承接总工分配的具体开发任务；遇到瓶颈先自行判断，判断不了汇报总工。

## 2. 模块交付物（每个模块固定一套）

| 文件/目录 | 用途 |
|---|---|
| `brief.md` | 模块任务书：目标、范围、交付物、验收标准（开工前由总工撰写） |
| `risks.md` | 风险预判清单：登录态/账号/API/浏览器/数据/环境等，逐条给出应对方案（开工前撰写） |
| `progress.md` | 进度看板：任务列表、完成度%、剩余工作、**迭代版本号**（v1.0/v1.1/…） |
| `decisions.md` | 决策记录：关键技术决策、理由、备选方案 |
| `BLOCKERS.md` | 阻塞上报区：总工解决不了的问题写这里（格式见第 6 节） |
| `context/` | **模块上下文库**：数据字典、API 契约、跨模块数据契约、环境事实（防数据污染的关键） |
| `database/` | **模块数据库**：Schema DDL、迁移脚本、数据导出快照（开发库文件在 `backend/data/db/<模块>.db`，不入 git） |

## 3. 进度、台账与踩坑日志（写文件纪律）

1. **进度看板** `progress.md`：总工持续维护。每个任务一行：`[ ] 任务名 | 负责:xxx | 进度:x% | 剩余:yyy`。任务完成即时勾选并更新百分比。
2. **工作台账** `_management/logs/agent-activity.md`：**每一个代理**（总工和子代理）在完成一段工作后，追加一行记录：
   ```
   ### YYYY-MM-DD HH:MM | <代理名/ID> | <模块> | 角色(总工/子代理)
   - 完成任务：...
   - 产出文件：...
   - 当前阻塞：...
   ```
3. **全局踩坑日志** `_management/logs/pitfall-log.md`：任何代理遇到问题（无论是否解决）都必须登记：
   ```
   ## P-<编号> <问题一句话>
   - 出现时间 / 模块 / 代理
   - 现象与根因
   - 解决方案
   - 防复发措施（必须在代码/文档中落实）
   ```
   开工前必须检查踩坑日志，确认没有已记录的坑。
4. **数据联动审计** `_management/logs/data-audit.md`：所有跨模块数据调取必须在此登记（见第 5 节）。

## 4. 模块数据库隔离与上下文库（防数据污染铁律）

1. **一模块一库**：每个模块只使用自己的数据库文件 `backend/data/db/<模块ID>.db`，**严禁读写其他模块的库文件与表**。
2. **表名前缀**：模块内新增表一律加模块前缀（如 M2 素材模块的表 `asset_*`、M5 投放模块的表 `ad_*`），避免与基座表冲突。
3. **共享表只读**：基座 M0 拥有的共享表（`workflow_jobs`、`app_config`、`logs` 等），其他模块只能读取，写入必须通过总控协调。
4. **上下文库**：`context/` 目录是模块的持久记忆，跨会话不丢失。数据字典、外部 API 契约、环境变量清单（不含明文密钥）都写在这里。
5. **密钥纪律**：任何 API Key / Token / Cookie / 密码**绝不写入任何 md 文件、代码、日志**；一律走环境变量，日志输出必须脱敏。

## 5. 跨模块数据联动协议

1. 模块 A 需要模块 B 的数据时，A 的总工**不得直接读取 B 的库**，必须：
   - 在本模块 `context/data-requests.md` 登记需求（要什么字段、什么用途、频率）；
   - 写入 `_management/logs/data-audit.md` 登记数据调取申请；
   - 汇报总控，由总控转达 B 的总工。
2. B 的总工提供数据时，须在 `data-audit.md` 记录「提供了什么、校验结果、快照位置」，并汇报总控。
3. 总控负责核对数据口径一致（字段名、单位、时间格式），核对结果记入 `data-audit.md`。
4. 数据交接的正式载体：双方约定一个 JSON 文件或只读视图，放在 `_management/data-exchange/<交换名>.json`，双方总工共同签字（在文件头记录双方代理 ID）。

## 6. 阻塞与升级协议

1. 子代理遇到瓶颈 → 先自己尝试判断/绕行；确实判断不了 → 写报告给本模块总工（在子代理工作目录内写 `REPORT.md` 并结束回合）。
2. 总工判断不了 → 在模块 `BLOCKERS.md` 追加一条：
   ```
   ## BLOCKER-<编号> <日期> <标题>
   - 现状：...
   - 已尝试：...
   - 需要总控/用户决策：...
   ```
   然后**结束当前回合**（不要空等），总控读取后回复决策。
3. 总控决策不了的 → 总控在会话中向用户汇报，用户决策后由总控下发。
4. **结束回合 = 向总控发信号**：总工完成一段工作或上报阻塞后，必须结束回合，让总控收到完成通知。

## 7. 备份与 git 纪律

1. **总控唯一执行 git 操作**。任何代理（总工/子代理）**禁止运行 git 命令**，只需正常写文件。
2. 总控在关键节点执行：提交（commit）→ 打标签（tag）→ 推送 GitHub 备份仓库。
3. 标签命名：`v<迭代版本>`（如 `v0.1`、`m1-v1.0`），保证每步可回退。
4. 重要状态文件（进度/决策/踩坑日志/数据审计）变化即提交，代码按「可运行里程碑」提交。
5. 浏览器资料（登录态）与数据库文件不入库、不上传，符合风控纪律（见 `10-风险合规与风控清单.md`）。

## 8. 企业级质量标准（所有代码交付必须满足）

1. **可测试**：每个功能模块必须配套单元测试；修改必须跑通既有测试。
2. **幂等与断点**：所有写入幂等；失败可重试、可断点续跑（沿用 WorkflowJob 错误码体系）。
3. **错误分类**：复用错误码表 `VERIFICATION_REQUIRED / AUTH_REQUIRED / RATE_LIMIT / TIMEOUT / NO_MATCH / PLATFORM_REJECT / UNEXPECTED`。
4. **配置化**：硬编码路径、类目白名单、权重、阈值全部走配置（环境变量或 `app_config`）。
5. **日志留痕**：关键操作写日志，敏感信息脱敏；操作留证据 JSON。
6. **文档同步**：代码行为与设计文档不一致时，要么改代码要么更新设计文档，并记入决策记录。
7. **安全**：管理后台需鉴权；CORS 收口；密钥环境变量化。

## 9. 子代理管理规范（仅总工适用）

1. **总工 = 独立会话**：每个模块总工程师是一个独立的代理会话，负责自己模块的开发全流程管理；总工在其会话内**亲自创建并管理子代理**（使用 subagent 工具，后台运行），一个子代理对应一个明确、可验收的任务。
2. **总工职责边界**：总工负责模块的架构设计、任务拆解、子代理任务书编写、进度管理、验收与集成；**具体开发任务必须通过子代理分派**，总工不得把自己降级为普通开发（可承担少量核心/骨架代码，但批量任务必须下放）。
3. **子代理任务书自包含**：背景、目标、输入文件路径、输出文件路径、验收标准、宪法要点（子代理看不到总工会话上下文，任务书必须完整）。
4. 子代理完成后总工必须验收（读产出、跑测试），验收不合格退回修改；子代理的产出与问题登记到 `agent-activity.md` 与 `BLOCKERS.md`（如有）。
5. 子代理汇报/阻塞走宪法第 6 节协议（子代理 → 总工 → 总控 → 用户）。
6. 总工对模块交付物负最终责任。

## 10. 汇报节奏

- 总工每个工作回合结束时，在 `progress.md` 更新进度，并在 `agent-activity.md` 登记。
- 总控汇总各模块状态到 `_management/dashboard.md`，并向用户汇报关键进展与待决事项。
- 阻塞必须第一时间上报，不积压。

## 11. 文件编码纪律（UTF-8 铁律，违反即乱码事故）

1. 所有文本文件（.md/.py/.json/.yaml 等）**一律 UTF-8**，写文件优先使用文件写入工具（write/edit，自动 UTF-8 无 BOM）。
2. **禁止**用 PowerShell 的 `Add-Content`/`Set-Content`/`>` 重定向写中文文本（Windows PowerShell 5.1 默认 ANSI/GBK，会污染 UTF-8 文件）。如必须用 PowerShell 写文件，使用：
   `[System.IO.File]::WriteAllText($path, $content, (New-Object System.Text.UTF8Encoding($false)))`
3. 追加已有文件时，先确认目标文件编码为 UTF-8，再以 UTF-8 追加；不要混用带 BOM 与无 BOM 写入同一文件。
4. 读取中文文本文件时，若显示乱码，请用 UTF-8 显式解码（`[System.IO.File]::ReadAllText($path, [System.Text.Encoding]::UTF8)`），不要用默认编码读取后误判内容损坏。
5. 违反本条款的文件在提交前必须修复（统一转 UTF-8 无 BOM）。
