## 0. 全局约定（v6）

### 0.1 主键与标识
- 内部主键 `id bigint generated always as identity`；外部/API/证据/幂等引用 `public_id uuid not null default gen_random_uuid()`。
- FK 一律 bigint；业务唯一性用组合 UNIQUE / 部分唯一索引 / 排他约束。

### 0.2 字段矩阵
| 表类别 | 必带 |

| 主数据 | `tenant_id`、`status`、`created_at`、`updated_at`、`row_version`、`deleted_at`（软删：部分唯一 `WHERE deleted_at IS NULL`） |

### 0.4 组合 FK 契约（v6 单一规则）
- **凡子表同存 `tenant_id` 与 tenant-owned 父表 id，一律组合 FK**：`FOREIGN KEY (tenant_id, parent_id) REFERENCES parent(tenant_id, id)`；
- **所有父表带 `UNIQUE (tenant_id, id)`**（见各表）；
- **global policy 例外（v6 裁决）**：`policy_versions.tenant_id` 允许 NULL（系统模板）。对 policy 的引用**不使用组合 FK**，改用命名普通 trigger `trg_<表>_policy_ref`：语义 =「引用的 policy 与行同 tenant，或 policy 为 global（tenant_id IS NULL）」。其余 tenant-owned 父表一律组合 FK；
- **polymorphic 引用例外**（明确登记，不混写普通 FK）：`cost_snapshots.decision_object_id`、`manual_tasks.ref_id`、`asset_reviews.scope_ref_id`——由命名 trigger + 应用层校验（见 §9 例外登记）；
- **跨父实体一致性**用命名普通 `BEFORE ... FOR EACH ROW` trigger（非带 SELECT 的 CHECK、非 constraint trigger），见 §8；
- 不再出现带 SELECT 的 CHECK、不再出现"服务断言"占位语句。

### 0.5 NULL 唯一（v6 正式语法）
- 业务唯一键含可空列一律 **PostgreSQL 15 正式语法**：`UNIQUE NULLS NOT DISTINCT (col1, col2)`（关键字在列清单前）；或对应 `CREATE UNIQUE INDEX ... NULLS NOT DISTINCT`。

### 0.6 排他约束
- 依赖 `CREATE EXTENSION IF NOT EXISTS btree_gist`（migration 顶部）；
- `policy_versions` 排他用 `scope_key` 生成列 + `COALESCE(tenant_id,0)`（见 §6.5）；
- `pricing_decisions` 排他见 §4.3。

### 0.7 身份与租户成员（better-auth 契约，保持 v3/v4）
- users（better-auth 管理）：`id uuid`、`email`、`status(active/disabled)`；
- tenant_members（better-auth 管理）：`user_id`、`tenant_public_id`、`role(admin/operator/viewer)`；
- 业务表 `actor_id uuid` 引用 users.id 或 `actor_registry`（system/worker/service），不建跨外部 schema FK；
- 审计 join：先 registry 后 users；P1 可启用 RLS session 变量，P0 用组合 FK + 应用断言。

### 0.8 金额/时间/保留
- **CID 计算输入 K/J/I/H/G/L 用 `numeric(18,6)` 分**（保留 Excel 小数分，v6 关键修订）；业务结算字段另存 `*_rounded_cents bigint`；
- 时间 timestamptz UTC；枚举英文；敏感 public/internal/secret；保留未注即永久。

## 7. CID 盈亏公式（v6，按原件冻结 + 高精度一次计算）

存入 `policy_versions(policy_type='cid_breakeven', version='v5', scope_type='global', scope_key='<global>', tenant_id=NULL)`：

| 字母 | 业务名 | 公式（原件） | 精度 |
|---|---|---|---|
| K | 客单 | 输入 | numeric(18,6) 分 |
| J | 技术服务费 | 输入 | numeric(18,6) 分 |
| I | 退货预留 | 输入 | numeric(18,6) 分 |
| H | 运费 | 输入 | numeric(18,6) 分 |
| G | 产品成本 | 输入 | numeric(18,6) 分 |
| L | 电商税 | 输入 | numeric(18,6) 分 |
| M | 利润 | `K−J−I−H−G−L` | 高精度一次计算 |
| N | 盈亏roi | `K/M` | 高精度一次计算 |
| O | 预计roi | `N + roi_buffer` | 高精度一次计算 |
| P | 预估roi出价 | `K/O` | 高精度一次计算 |
| Q | 消耗返点 | `P × consumption_rebate_rate` | 高精度一次计算 |
| R | 技术返点净调整 | `K×tech_hi − K×tech_lo` | 高精度一次计算 |
| S | 预估利润 | `K−P−J−I−H−G+R+Q`（原件不减 L） | 高精度一次计算 |
| T | 加返点利润率 | `S/P` | 高精度一次计算 |
| U | 回传数 | 输入（0.4/0.5） | numeric(8,4) |
| V | 扣回传最高出价 | `P/U` | 高精度一次计算 |
| X | 扣回传最高roi出价 | `O×U` | 高精度一次计算 |

**精度与取整规则（v6 冻结，可复现 Excel 第 2 行）**：
1. **输入持久化**：K/J/I/H/G/L 以 `numeric(18,6)` 分保存（保留 Excel 小数分，如 J=13.194、I=153.930、L=83.562），**入库不得按分四舍五入**；
2. **公式引擎**：使用统一高精度 decimal 上下文**一次性算完 M~X**（不读取已量化的中间投影），随后才分别量化持久化；
3. **持久化**：`pricing_decisions.cid_results` 保存 M/N/O/P/Q/R/S/T/V/X 未取整值 + 公式版本 + rounding mode；`bid_rounded_cents bigint` 为平台提交价（round 到分）实体列；`cost_snapshots` 保存 CID 输入与中间 M/Q/R；
4. **比率**：N/O/T/X 量化到 `numeric(12,6)`（仅持久化，不回流参与后续计算）；
5. **除零**：`M=0`、`O=0`、`U<=0`、`P=0` → 不进入出价计算，标记 `insufficient_data`；负/零 M 硬拒绝；
6. **空值**：`L` 缺失按 0 但标记；`Q/R` 的「无返点」与「来源缺失」分开（`rebate_applicable=false` vs `field_missing`）；
7. **负毛利**：`M<=0` 或 `S<=0` → 人工闸门/退出上架；
8. `W`（溢价）、`Y`（消耗）不在核心公式链，标扩展/未确认。

## 8. trigger 契约（v6：普通 BEFORE ROW trigger，非 constraint trigger）

> **分类裁决**：17 个 trigger 全部为**普通 `BEFORE ... FOR EACH ROW` trigger**（即时校验），**不使用 `CREATE CONSTRAINT TRIGGER`**（PostgreSQL constraint trigger 仅适用于 AFTER ROW；本字典所有校验都在行写入时对既有父行查询，BEFORE 即可）。已删除 deferrable 待定项与「constraint trigger」表述。

| trigger 名 | 表 | 时机/事件 | 校验键/语义 | 错误码 |
|---|---|---|---|---|
| trg_shops_policy_ref | shops | BEFORE INSERT OR UPDATE OF cid_policy_version_id, tenant_id | cid_policy_version_id 指向 policy 同 tenant 或 global | INVALID_POLICY_REF |
| trg_offers_sku_product_consistency | supplier_offers | BEFORE INSERT OR UPDATE OF sku_id, product_id, tenant_id | sku_id 非空时，product_skus.product_id = 行 product_id | SKU_PRODUCT_MISMATCH |
| trg_cost_policy_ref | cost_snapshots | BEFORE INSERT OR UPDATE OF policy_version_id, tenant_id | policy 同 tenant 或 global | INVALID_POLICY_REF |
| trg_cost_context_consistency | cost_snapshots | BEFORE INSERT OR UPDATE | decision_object/shop/listing/offer 同源一致（polymorphic 按 objtype 校验） | CONTEXT_MISMATCH |
| trg_selection_policy_ref | selection_decisions | BEFORE INSERT OR UPDATE OF policy_version_id, tenant_id | policy 同 tenant 或 global（非空时） | INVALID_POLICY_REF |
| trg_bindings_sku_product_consistency | asset_product_bindings | BEFORE INSERT OR UPDATE OF product_sku_id, product_id, tenant_id | sku 非空时其 product 与行内一致 | SKU_PRODUCT_MISMATCH |
| trg_shopbind_context_consistency | asset_shop_bindings | BEFORE INSERT OR UPDATE | asset_product_binding 的 product/asset 与行内一致；listing 的 shop 与行内一致 | CONTEXT_MISMATCH |
| trg_listings_account_shop_consistency | shop_listings | BEFORE INSERT OR UPDATE OF account_id, shop_id, tenant_id | listing 的 shop 属于该 account | ACCOUNT_SHOP_MISMATCH |
| trg_pricing_policy_ref | pricing_decisions | BEFORE INSERT OR UPDATE OF policy_version_id, tenant_id | policy 同 tenant 或 global | INVALID_POLICY_REF |
| trg_pricing_context_consistency | pricing_decisions | BEFORE INSERT OR UPDATE | shop/listing/listing_sku 上下文一致（listing_sku 属于 listing、listing 属于 shop） | CONTEXT_MISMATCH |
| trg_campaigns_scope_consistency | ad_campaigns | BEFORE INSERT OR UPDATE OF account_id, shop_id, shop_listing_id, tenant_id | shop_listing 的 shop/account 与行内一致 | SCOPE_MISMATCH |
| trg_campaigns_policy_ref | ad_campaigns | BEFORE INSERT OR UPDATE OF budget_policy_version_id, cid_policy_version_id, tenant_id | 两个 policy 同 tenant 或 global | INVALID_POLICY_REF |
| trg_campassets_same_scope | ad_campaign_assets | BEFORE INSERT OR UPDATE | campaign 与 binding 同 tenant/shop | SCOPE_MISMATCH |
| trg_snapshots_dimension_consistency | ad_report_snapshots | BEFORE INSERT OR UPDATE | account/shop/listing/sku/product/campaign/asset 维度同源一致 | DIMENSION_MISMATCH |
| trg_feedback_dimension_consistency | roi_feedback_events | BEFORE INSERT OR UPDATE | 冗余维度与 source_snapshot 一致 | DIMENSION_MISMATCH |
| trg_manual_policy_ref | manual_tasks | BEFORE INSERT OR UPDATE OF policy_version_id, tenant_id | policy 同 tenant 或 global（非空时） | INVALID_POLICY_REF |
| trg_policy_supersede_scope | policy_versions | BEFORE INSERT OR UPDATE OF supersedes_id, tenant_id, policy_type, scope_type, scope_id | supersede 同 tenant 且同 scope 同 type | SUPERSEDE_MISMATCH |

> round-61 受控勘误（R60-2）：`trg_policy_supersede_scope` 事件列在原冻结（supersedes_id, tenant_id）基础上补 `policy_type, scope_type, scope_id`——否则仅更新子 policy 的 type/scope 可绕过触发器，导致父子不同源仍提交。勘误后事件列与函数体依赖字段一致。

> 函数体（PL/pgSQL）在 P0-1 编写；本表冻结：目标表、`BEFORE ... FOR EACH ROW`、触发字段事件（含 `tenant_id`，保证引用行改租户时重新校验）、校验语义、错误码（错误码见上表「错误码」列，纳入统一错误码表，P0-1 生成迁移时并入 `enum_error_code`）。
